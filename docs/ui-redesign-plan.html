Design plan · Flutter · Material 3

TechByte UI Redesign

The theme layer is already good. What's missing is the discipline that makes it hold across fifteen screens — a token system nothing bypasses, a component set that stops the copy-paste, and a light mode that is actually legible.

Scope 15 screens · 22 UI files Codebase techbyte/lib Posture Dark-first, minimal, editorial
01

What I found

I read every screen. The foundation is more considered than most apps this size: one accent, restrained per-category hues, a real reason behind the type sizes, and comments that explain intent rather than mechanics. The problems are not taste problems — they are systems problems. Values that should live in one place live in twenty, and the light theme was never designed, only derived.

Findings are ranked by what they cost a user, not by how much code they touch.

Blocking
Light mode fails contrast everywhere it uses colour

All 18 category hues, plus the accent and all three semantic colours, are reused verbatim in light mode. They were tuned for a #0A0C0F ground. On #FBFCFD not one of them reaches 4.5:1 — the worst sits at 1.44:1. This is rendered at 11.5px as the category label above every single question.

02

Principles this plan is built on

Six ideas decide every call below. Where two conflict, the earlier one wins.

The question is the interface

Everything else is chrome. Chrome gets quieter, never louder. No decoration competes with 32px of display type on an empty ground.

One emphasis per screen

Von Restorff: a highlight only reads as one if it's alone. Right now the accent carries category identity, the reveal action and progress. Split those jobs so the accent means "the thing to do next".

Spacing is grouping

Gestalt proximity does the work that borders and dividers are currently doing. A strict 4pt scale with meaningful jumps replaces the ad-hoc values, and most existing dividers come out.

Progressive disclosure, already the core mechanic

The reveal gesture is the product's best idea. Extend the same logic outward: Profile shows identity and progress, settings sit one level down.

Every state is a designed state

Loading, empty, error and offline get the same care as the happy path, from the same three components — not improvised per screen.

Accessible by construction

WCAG 2.2 AA is a build constraint, not a review step: 4.5:1 text, 3:1 non-text, 44px targets, colour never the only channel, one motion switch that governs everything.

Space, radius, motion, depth

Spacing — 4pt base

4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64. Two page gutters, each justified by measure rather than preference: gutter = 20 for every list and detail screen, gutterReading = 24 only where display-size type sets the line length — the feed card and onboarding. Everything else picks the nearest step; 6, 10, 14, 18, 22 and 26 disappear.

Radius

sm 8 · md 12 · lg 16 · xl 20 · full 999. 14 and 18 are removed. Cards and sheets take xl, panels and buttons lg, inputs and notices md, inline chips sm.

Motion

fast 140ms for state flips, base 220ms for navigation and sheets, reveal 380ms for the one signature moment. Curves: easeOutCubic standard, easeOutQuint for the reveal alone. All three route through a single Motion.of(context) that collapses to Duration.zero when either the app preference or MediaQuery.disableAnimationsOf asks it to — which fixes the two sites that currently ignore the setting.

Depth — three tiers, not one

The app is uniformly flat: every surface is elevation 0 with a 1px outline, so a modal sheet, a card and a floating overlay read identically. Three named tiers replace that. Ground: scaffold, no border. Raised: surface + hairline, still no shadow — cards, panels, tiles. Overlay: raised tone + hairline + one soft shadow — sheets, menus, snackbars, the daily strip. In dark mode the overlay tier lifts tone and brightens its border instead of relying on a shadow nobody can see.

04

Foundation: the component layer

Ten widgets in lib/app/ui/. Each one exists because the same thing is currently written between two and seven times. This is where the consistency actually becomes structural rather than aspirational.

AppPanel

Tinted box + hairline. Variants: plain, mono, notice. Replaces 7 copies.

AppEmptyState

Icon, title, body, optional action. Replaces 6 copies.

AppErrorState

Human message, collapsible detail, retry. Replaces 4 raw dumps + 1 good one.

AppSkeleton

Shimmerless tone-pulse blocks, plus three presets shaped like the feed card, the tile grid and the question list. Replaces 6 spinners.

MeterRow

Label + 6px track + tabular value, with a real Semantics value. Replaces 3 implementations.

QuestionTile

The Card + ListTile that opens the deep-dive sheet. Replaces 3 copies.

CategoryMark

The accent bar + uppercase label lockup. Replaces 4 copies across card header, sign-in, splash and explore.

SectionHeader

Eyebrow + optional one-line description, on the standard spacing step.

StatTile

Figure + label, with primary and secondary weights so four numbers stop shouting equally.

AppButton sizes

lg 52 primary CTA, md 44 inline, sm 36 in sheets — all still clearing the 44px touch target via padding.

05

Screen by screen

Feed — the one screen that must not change much

It works. Changes are corrective and additive only.

  • Move the daily strip from a free Positioned overlay into the card's own header row, so it can never collide with the question. It keeps its floating treatment and gains the overlay depth tier.
  • Bookmark and overflow buttons go to full density — 44px targets.
  • Question type steps to displayLarge (34px) and the reading gutter to 24, tuning the measure to ~34 characters per line.
  • The reveal keeps its 380ms expansion but gains a 60ms accent-bar flash on the category mark, so the causal link between tap and reveal is visible at the top of the screen too.
  • Swipe affordance becomes a persistent low-opacity chevron rather than text, and appears only on the first three cards of a session.

Explore — the biggest functional gain

  • Tiles become tappable, pushing a filtered question list for that category. This is the missing route from taxonomy to content.
  • Tile rebuilt on Card + InkWell, so it inherits the radius and gets a real press state.
  • Sort by engagement, not enum order, and separate "in progress" from "not started" — 18 identical tiles in declaration order is a wall.
  • Search moves from the app-bar icon to a persistent pinned field, matching Saved, so there is one search pattern.
  • Grid loading becomes a tile skeleton.

Profile → Profile + Settings

  • Settings move to their own screen behind a single row. Profile keeps identity, stats, familiarity and History — four blocks instead of eleven decisions.
  • Stats drop to three primaries (Viewed, Completed, Saved) with "Available" demoted to a caption; a catalogue size is context, not an achievement.
  • Familiarity rows use MeterRow and gain semantics.
  • "Delete account" moves to the bottom of Settings, inside a bordered danger region, separated by a full section break — not 10px under Sign out.
  • _dailyBudgetLabel()'s hardcoded '40' reads from ai_config.dart.

Practice

  • Disabled mode cards drop Opacity for explicit muted tokens, keeping body text above 4.5:1.
  • The grading result gets a clear three-part rhythm — verdict, dimensions, ideal answer — with the score figure at displayMedium and the band label paired with an icon so the verdict is not colour-only.
  • Metric and evaluation rows share MeterRow; the metrics block becomes AppPanel.mono.
  • Grade-scroll animation respects reduced motion.

Saved · Search · History

  • All three adopt QuestionTile, so a question looks the same wherever it appears.
  • History status becomes an icon + label chip rather than green text.
  • Search suggestions come from the user's actual most-seen categories rather than a hardcoded eight-term list.
  • All three get skeletons, real empty states and real error states.

Onboarding · Sign-in · Splash

  • Page transitions respect reduced motion.
  • Onboarding topic chips show their category colour as a leading dot — the first time the user meets the colour language, which pays off on every later screen.
  • Sign-in gets a proper Google mark asset instead of Icons.g_mobiledata_rounded.
  • Splash and sign-in share the CategoryMark lockup so the transition is genuinely continuous, which the comment already claims it is.

Shell

  • Icons standardise on the rounded set throughout, matching the geometry everywhere else.
  • Nav bar takes the overlay depth tier so it separates from the feed's full-bleed ground.
  • A small dot on Practice when review items are due — currently that count is only discoverable by opening the tab.

How we'll know it worked

  • Zero colour pairs below 4.5:1 for text or 3:1 for non-text, in both themes — re-run the same measurement that produced the tables above.
  • No literal spacing, radius, duration or colour value in any file under features/**/presentation/.
  • Every async surface has all four states, sourced from the shared components.
  • Every interactive target ≥ 44 × 44.
  • Turning on Reduce motion stops every animation in the app, not one.
  • The app is navigable end to end with TalkBack, with meaningful values on all progress meters.
  • No layout breaks at system text scale 2.0.

One thing I'd flag before starting: the dark theme is genuinely well judged, and the temptation in a pass like this is to redesign it because we're in there anyway. The plan deliberately does not. Dark mode changes only where a shared component or a measurement forces it — everything else is the light theme catching up, and the structure catching up with both.
